# AGENTS.md

## Project
LampZ Sync is a Tauri v2 desktop app that samples a monitor and drives a Tuya
lamp to match the dominant screen color.

- Frontend (React + TypeScript + Tailwind): `src/`
- Backend (Rust + Tauri): `src-tauri/`

## Commands
| Task | Command |
| --- | --- |
| Install deps | `bun install` |
| Typecheck + build frontend | `bun run build` |
| Frontend dev server | `bun run dev` |
| Run the desktop app | `bun run tauri dev` |
| Regenerate TS types from Rust | `bun run bindings` |
| Rust typecheck | `cargo check` (workdir `src-tauri`) |
| Rust tests | `cargo test --lib` (workdir `src-tauri`) |

There is no linter configured. `bun run build` (runs `tsc`) and `cargo check`
are the verification steps.

## Architecture

```
React state (src/App.tsx)
  -> invoke("<command>")            src/lib/commands.ts
  -> #[tauri::command] fn           src-tauri/src/commands.rs
  -> update_config(...)             mutate Config + bump revision + publish + save
  -> workers read AppState.config   lamp_thread.rs / capture_thread.rs
```

`AppState.config` (`RwLock<Config>`) is the **single source of truth**. The
`LampMailbox` carries only the high-frequency color stream plus a `config_epoch`
that wakes workers. Every persisted change goes through the one helper
`update_config` in `commands.rs`, which:

1. mutates `Config` under the write lock,
2. bumps `Config::revision`,
3. publishes the revision to the mailbox and notifies the condvar,
4. saves to the Tauri store.

Workers compare their last-seen revision against `Config::revision` and re-read
the snapshot when it changes, so no config field can be silently missed.

### Key files
| File | Responsibility |
| --- | --- |
| `src-tauri/src/config.rs` | `Config`, `LampTuning`, `LampConnection` (persisted schema) |
| `src-tauri/src/app_state.rs` | `AppState` + `LampMailbox` |
| `src-tauri/src/commands.rs` | Tauri commands + the `update_config` helper |
| `src-tauri/src/app_store.rs` | Load/save `Config` via the store plugin |
| `src-tauri/src/lamp_thread.rs` | Reads config, drives the lamp |
| `src-tauri/src/capture_thread.rs` | Screen capture + color detection |
| `src-tauri/src/detector.rs` | Dominant-color detection, `CaptureRegion` |
| `src/lib/commands.ts` | Frontend wrappers; re-exports generated types |
| `src/lib/bindings/` | **Generated** TS types (do not edit by hand) |
| `src/App.tsx` | UI state and panels |

## Adding a new option

### A. A tuning slider (fits `LampTuning`)
This is the common case and needs **no changes** to `commands.rs`, `lib.rs`, or
the worker threads.
1. `config.rs`: add the field to `LampTuning` **and** its `Default` impl.
2. `bun run bindings`: regenerate TS.
3. `src/App.tsx`: add it to `defaultLampTuning` and render a `<SliderControl>`.
   (`SliderControl` already accepts any `keyof LampTuning`.)
   If a `u64`/`i64` value is always a safe JS number, annotate it in Rust with
   `#[ts(type = "number")]` (otherwise ts-rs emits `bigint`).

### B. A general config field (not tuning)
1. `config.rs`: add the field to `Config` **and** its `Default` impl, and give
   it `#[serde(default)]` (or a `default = "..."` fn).
2. `bun run bindings`.
3. `commands.rs`: add a `#[tauri::command]` that calls
   `update_config(&app_handle, state.inner(), |config| { ... })`.
4. `lib.rs`: register the command in `generate_handler!`.
5. `src/lib/commands.ts`: add an `invoke` wrapper and re-export any new type.
6. `src/App.tsx`: add state, call the command, render a control.
7. If a worker must react, add one branch in `lamp_thread::apply_config` or the
   config block in `capture_thread.rs`.

## Rules
- **Every `Config`/`LampTuning` field must have a serde default.** `app_store`
  falls back to `Config::default()` when deserialization fails, so a field
  without a default silently wipes all user settings on upgrade.
- **Never rebuild `Config` field-by-field.** Mutate through `update_config`;
  this was the previous bug in `connect_lamp`.
- `src/lib/bindings/` is generated by `ts-rs`. Regenerate with `bun run
  bindings`; never edit it manually.
- ts-rs maps 64-bit integers to `bigint`. Tauri serializes them as JSON numbers,
  so add `#[ts(type = "number")]` whenever the value is safe as a JS number.
